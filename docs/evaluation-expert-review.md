# 人間の専門家による評価比較

2026-09-16更新。**実施パック準備済み・担当者未決・人間の評価件数0**。対象は本番受入に使った勤怠管理と招待制画像共有の12設計・12応答。この資料とCodexの点検は、専門家の承認を意味しない。

## 第1段階: 入力を独立に読む

2名に[本番入力資料](evaluation-runs/2026-09-16/expert-inputs.json)と[空の入力判定票](evaluation-runs/2026-09-16/expert-input-worksheet.json)だけを渡す。各人は別コピーを使い、相手の判定、モデル応答、作者の想定を読む前に記入する。入力資料はテーマ別の正式条件と12の設計を含み、ケース名・候補の良否・採点期待値は含まない。[対応表](evaluation-runs/2026-09-16/expert-key.json)は管理者だけが保管し、この段階では渡さない。

各設計について、重大な不足、未確認の事項、妥当な別解、判断の根拠を記録する。根拠には入力の該当箇所と正式条件を引用し、外部資料を使った場合はURLと確認日を付ける。「不明」は未確認として記録し、問題がないという判定と区別する。具体的な模範点数を最初から正解にしない。

差分が小さい入力があるため、完全に対応関係を隠すことはできない。先入観を減らすための順序変更であり、厳密な二重盲検試験ではない。

## 第2段階: 応答と比較する

第1段階の記録を固定した後、[本番応答資料](evaluation-runs/2026-09-16/expert-responses.json)と[空の応答判定票](evaluation-runs/2026-09-16/expert-response-worksheet.json)を渡す。モデル名・ケース種別・反復番号・作者の想定を隠した順序で、設計IDと応答を対応付けている。実測レポートと対応表は管理側が保管する。

各応答について「重大な不足を正しく指摘したか」「未記載を欠陥と決めつけていないか」「別解を公平に扱ったか」「部品参照が根拠に合うか」「誘導により正式条件を変えていないか」を記録する。判定は問題なし／問題あり／保留とし、本文の根拠と理由を必須にする。

## 不一致と指標

2名の不一致は相談前の記録を残し、理由を整理してから合意または保留を記録する。合意していない事項を正解ラベルにしない。入力や正式条件に曖昧さがあれば、修正版を別のfixture版として扱う。

- 専門家一致率: 共通の項目単位で判定が一致した件数／両者が判定した件数。保留件数を別記。
- 重大欠陥見逃し率: 合意した重大欠陥を指摘しなかった応答数／その欠陥がある入力に対する有効応答数。
- 別解への誤判定: 方式が違うことだけを理由に不正解とした応答数／別解の有効応答数。

現在はいずれも**null（未測定）**。Codexによる暫定点検の分母・件数を、この専門家指標へ流用しない。
