## 実装した体験

全8ステージの体験・練習、見積もり、卒業課題で同じReact Flowキャンバスを使う。ボタン／ドラッグで部品を追加し、位置を動かし、接続点か選択欄で線を作る。選択した部品・線の削除、Undo/Redo、キーボード移動、拡大縮小に対応する。旧3種類の固定UIはこの共通画面へ置き換えた。

| 操作 | 図に応じて変わること |
| --- | --- |
| ブラウザから送る | 接続の向きが違う、途中で切れる場合は要求が届かない |
| アプリからDBへ保存 | 置いただけでは使えない。接続して保存し、再起動後に読み出す |
| Load Balancerを挟む | 接続されたアプリに振り分ける。A/Bそれぞれの停止と残る能力を反映 |
| キャッシュを接続 | コピーから読む。未接続ならDBへ。古い表示と無効化後を比較 |
| キューとWorkerを接続 | 受付・待機・実行を区別。未接続／停止中のWorkerは処理しない |
| API Gatewayを挟む | 迂回する経路が残ると制限を適用しない。7件の完了と再試行待ちを確認 |
| 図で実験する | 代表的な1件の経路をハイライトし、順に追える |
| 図や実験条件を変える | 現在の構成で再度試してから到達を確認。理由だけの正答では通過しない |
| 卒業課題から進む | 実際に配置した部品ID・位置・接続と理由を、自由設計とJSONへ引き継ぐ |

パレットはWeb Browserから順に1〜8種類。体験では今回の部品まで、練習では体験済みの今回の部品までを使う。自由設計の全32種類への入口は維持する。アプリはLoad Balancer以降2台、それ以外は各1個、接続24本まで。

これは入門用の簡略モデル。負荷分散を通らないアプリへの複数経路は名前順の1台に送る。DBや入口の故障、通信時間、実システムの性能は再現しない。使わない部品も図に置けるが、配置だけで機能が有効にはならない。卒業課題の部品数には未接続の部品も含める。

## 保存と移行

`architecture-sandbox:component-stages:v4` に体験と練習の図を別々に保存する。図の台数・種類・位置・接続・稼働状態を検証して読み込む。旧v3の観察、クリア履歴、修了履歴は保持し、旧キーは変更しない。旧v1/v2からの移行にも対応する。

旧記録に新しい図を確認した証拠はないため、復習時は図をつないで試す。学習記録全体の端末間同期・JSON出力は今回の対象外。卒業課題で引き継いだ図とメモは従来のプロジェクトJSONへ保存できる。設計保存のschemaVersion 3と公開API契約は変更していない。
