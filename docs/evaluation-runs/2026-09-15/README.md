## 本文の点検

以下は**Codexによる暫定点検**。人間の専門家指標には算入しない。32要求すべての点検記録と懸念は[codex-review.json](codex-review.json)。

- 最終候補の明示的データ消失は、通常入力2件・条件上書き2件の**4/4応答**で重大な矛盾として指摘。正式条件の上書きは0/2、全100点化は0/2、方式の違いだけによる別解の拒否は0/2。
- 部品名と接続のみの入力は、v2で2/3件が未記載を重大な不足に分類した。v3では0/2件。ただし、費用・実現性はどちらも70点で、入力の根拠より高い。費用が未確認の他ケースにも60〜75点が付き、採点基準との整合は不十分。
- v2では、元の同期保存を非同期・定期バックアップ等へ弱める提案が3/18件あった。v3の12件にはこの明示的な置換提案はなかった。ただし、改善案の検証が再起動・バックアップ復元に偏り、どの故障を対象にするかの確認は引き続き弱い。
- v3の機械的な存在チェックでは不正IDは0件。しかし`condition-override`の2回目は`[勤怠DB](#node=app)`で、存在する別ノードへリンクした。**意味上の誤参照は1/12応答**。v2でも同種の誤りが1/18件あった。存在チェック0件を正しい参照の証明にしない。
- 一部は3区分を一段落に詰め込むなど、Markdownの読みやすさにもばらつきがある。

## 修正した実装

生成要求にJSON Schemaを付け、必須項目・整数範囲・追加項目禁止を明示した。サーバーで重複キーを拒否する既存検証と総合点の再計算を維持し、実際に発生した重複キーを回帰テストへ追加した。キーやproviderのエラー本文をログへ出さず、自動再試行は行わない。

プロンプトでIDとラベル、未確認と重大な矛盾、停止許容とデータ消失許容を分けた。評価のみthinkingをlowに変更し、会話の設定は維持。プロンプトと設定を同時に変更したため、どちらの個別効果かは断定できない。意味の誤りはプロンプトやSchemaだけで保証できないため、残課題は閉じない。

## 実行の証跡・費用

Googleが返した`modelVersion`は全32件で`gemini-3.5-flash-lite`、`finishReason`は全件STOP、usageのserviceTierはstandard。初回の失敗はproviderのHTTPエラーではなく、アプリの厳密なパースによる拒否。要求先はGoogle公式generateContent APIで、コンパイル済みローカルバックエンドの実要求を使用。自動再試行0、モデル切替0。最大36要求に対して32要求で終了した。

入力$0.30・出力$2.50／100万トークンで算出。[Google公式料金](https://ai.google.dev/gemini-api/docs/pricing#gemini-3.5-flash-lite)。無料枠・割引・実際の請求額は未確認。出力はtotalTokenCount−promptTokenCountとしてthinkingを含める。thinking単独の件数は応答にないため0と断定しない。応答時間はアプリ往復を含む観測値であり、速度保証・有意な高速化ではない。

生の生成本文、アプリが受理した結果、使用量、要求／system instruction／fixture／ソース／バイナリのハッシュは[初回](baseline.json)・[v2](rubric2.json)・[最終候補](rubric3.json)。対応するプロンプトは同じディレクトリの`*-prompt.txt`に保存し、ハッシュ一致を確認済み。秘密・HTTPヘッダー・思考本文は保存しない。`complete: true`は予定要求の取得完了であり、品質の合格ではない。
