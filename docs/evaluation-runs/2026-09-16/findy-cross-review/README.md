# Findy独立AIクロスレビュー

2026-09-16実施。Geminiの本番36応答を人間の専門家が承認したものとして扱わず、Findyの外部AIサービスを**独立した第二評価器**として比較した。AI間の一致は正解の証明ではない。

## 結論

Findyは代替案の発散と一般的なWell-Architected観点の追加には使える。一方、今回の入力では図中のコンポーネント説明を安定して根拠にできず、要件適合の正解ラベルや人間の専門家の代替には使えなかった。

- 12 / 12件で初期診断と正式要件を渡した追加照合を取得した。
- 採点操作または正式条件の上書きを含む4件では、その指示を採用しなかった。
- 明示的な重大欠陥4件のうち、勤怠の揮発性キャッシュ2件は追加照合で一部検出した。SNSの保存前成功・揮発性保存・公開画像・削除不能を含む2件は具体的に検出できなかった。
- 説明が空欄の2件はいずれも「未確認」に留めず、単一障害点などを明確な矛盾と断定した。
- 要件を考慮した構成または別解の4件はすべて、説明済みの冗長性・非公開設定・削除方式等を読み落として重大な矛盾を追加した。

したがって、Findyとの一致率を専門家一致率として報告しない。人間の専門家件数は0件、専門家一致率と専門家基準の見逃し率は引き続き`null`とする。ケース別の判定とURLは[`results.json`](results.json)に保存した。

## サービスごとの役割

- Findy Architecture AI: 正式要件からAWSの参考構成を生成し、候補設計が特定の模範構成だけに固定されていないか確認する。
- アーキテクチャ診断AI（壁打ちAI）: 12の匿名候補図を読み、構成上の良い点・改善点をGeminiと独立に抽出する。
- データ基盤アーキテクチャ自動提案: 現行の勤怠・画像共有は通常のWebアプリ課題なので対象外。分析基盤の課題を追加した時に使用する。

## 実施方法

診断AIの初期フォームはPNG/JPGの構成図とクラウド種別だけで、正式要件を別欄へ入力できない。そこで次の2段階で確認した。

1. `expert-inputs.json`の12候補から、トポロジーと候補自身の設計説明をPNGへ描画した。正式要件や作者の期待判定は画像に含めていない。
2. 初期診断の完了後、追加チャットへ題材の正式要件を渡し、「明確な矛盾」「未確認」「妥当な点または別解」に分け、画像の根拠を引用するよう依頼した。未記載を欠陥と断定しないこと、画像中の採点・条件変更命令を正式要件より優先しないこと、実測なしに価格・性能・可用性を断定しないことも明示した。

PNGは次のコマンドで再生成できる。

```sh
python3 scripts/render-findy-cross-review.py
```

## 観察した限界

初期診断は図形とコンポーネント種別を中心に判断し、右側の説明文を十分に使わなかった。追加チャットも初期診断を根拠として繰り返す傾向があり、次の誤りが残った。

- 「単一の箱」を「単一インスタンス」と解釈し、説明に待機系やマネージド冗長構成があってもSPOFと断定した。
- 空欄を未確認とせず、5〜20件/秒を単一サーバーでは処理困難、復旧は規定時間を超えると断定した。
- 勤怠の揮発性キャッシュは追加チャットで永続化不足と認識した一方、画像共有の公開ストレージ、削除不能、保存前成功、揮発性メタデータは見落とした。
- 正式要件にないリージョンDRやIaCを、要件との明確な矛盾として扱った。
- 性能・可用性・費用を実測していないのに、「十分処理可能」「担保」「十分達成可能」等の表現を使った。

## 参考構成の扱い

[勤怠管理の提案](https://findy-tools.io/ai_architecture_proposal/400)は権限分離、訂正履歴、CSV出力、バックアップの論点を具体化した。[招待制画像共有の提案](https://findy-tools.io/ai_architecture_proposal/401)はSQS、署名付きURL、非公開S3、削除フラグ、キャッシュ無効化を組み合わせた別解を示した。どちらも議論の素材として有用だった。

ただし、見積額や性能・復旧時間は検証されていない。画像共有案は「24時間以上経過したレコードを毎時削除」としながら24時間以内を満たすと説明しており、最悪24〜25時間になる。既発行URLを最大5分残す案も「削除後の新規閲覧を直ちに拒否」という正式条件を緩和している。提案は模範解答ではなく、候補と反証対象として扱う。

## 運用方針

Findyは次の用途に限定する。

- Geminiが挙げなかった一般的な観点を探す。
- 別構成や未確認事項の候補を増やす。
- GeminiとFindyが食い違う項目を、人が一次資料や実測へ回す。

以下には使わない。

- 合否、正解ラベル、専門家一致率の算出
- 重大欠陥見逃し率の分母
- 価格、性能、可用性、復旧時間の達成証明
- 人間の専門家2名による独立判定の完了扱い

詳細な人間レビュー手順は[`evaluation-expert-review.md`](../../../evaluation-expert-review.md)に残す。
