# 設計の表現と保存形式

2026-09-15 / ローカル実装。公開APIのJSON構造は維持し、保存形式は追加情報がある場合だけv3にする。デプロイは別判断。

## 役割・実装・外部サービス

32種類の既存部品IDを維持する。部品の説明は役割の目安で、製品名を使う既存IDも破壊的に変更しない。任意の`data.design`で実装方式、担う仕事（アプリ・認証・API連携・通知・決済）、管理者（内部・外部）を分ける。外部サービスは既存の部品を配置して表示名を変更し、役割と管理者を指定する。新しい専門用語を初期パレットに大量追加しない。外部の認証・通知・決済は信頼性や重複実行の確認対象であり、存在だけで安全と認定しない。

## 配置とルール

- AWSのSubnetはVPCの一部で、1つのAZに属する。`Subnet.data.design.vpcId / zoneId`で別々に指定する。VPCがAZの子であるという単一ツリーにはしない。[AWS Subnets](https://docs.aws.amazon.com/vpc/latest/userguide/configure-subnets.html)
- 実行部品の`subnetId`はSubnetへの参照。Subnetを指定しない場合には`zoneId`も記録できる。両方記録した場合のAZ不一致、存在しない／種類の異なる参照先をブラウザで検出する。未指定は未確認。
- Security Groupは関連付けたリソースの許可通信を制御する。`securityGroupIds`は参照のリスト、SG部品の`rules`には方向・相手・方式・ポートを文字で記録する。実際のAWS API設定・ポート検査・到達性保証は行わない。[AWS Security Groups](https://docs.aws.amazon.com/vpc/latest/userguide/vpc-security-groups.html)
- `parentNode`は従来の図の整理と移動用に残す。採点プロンプトには、囲みから配置・通信許可・冗長性を断定しない指示を追加。新たなSGへの自動格納は停止。SGは実線と「通信の許可ルール」で表示する。旧SGの中の部品は保存した位置を保ち、記録の確認で関連付けを促す。
- 参照した部品を削除しても関連付けの記録を勝手に消さない。参照切れを表示し、設定で解除・選び直すかUndoで復元する。不完全な設計も保存できる。

## 接続・運用条件

`edge.data`に`payload`（渡すもの）、`protocol`、`mode`（sync/async）、`retry`を保存する。通信線と配置・SGの関連付けは別。線のラベルは渡すものを最大24文字表示し、全文は接続設定で読める。キーボードでも、部品から接続を選ぶか接続線でEnterを押して編集できる。

台数・実行単位数`replicas`は1〜1000、冗長化と切り替え`redundancy`、バックアップと復元`backup`、許容停止時間・データ損失の目標`recovery`は別項目。台数を増やすだけでは耐障害性の達成とは扱わない。`requirement`と`evidence`は利用者の記録で、根拠の有無だけで正式な合意や達成を認定しない。

## 保存とAPI互換性

| 対象 | 動作 |
| --- | --- |
| 旧Base64・JSON v2 | 読み込み可能。既存の座標・囲み・メモ・会話を維持 |
| 新設定を使わない作業 | 引き続きschemaVersion 2で書き出す |
| `data.design`または`edge.data`を持つ作業 | schemaVersion 3で書き出す。読み込み・自動保存・再開・削除欄からのバックアップを同じ正規化処理に通す |
| 旧アプリへのv3読み込み | 未対応バージョンとして拒否される。新しい情報を無言で捨てない |
| v3の参照切れ | 保存可能。ブラウザ内の確認で報告し、利用者が修正 |
| 不正な型・選択値・長さ・台数 | 保存／読込の正規化で拒否。任意のCSS・HTMLプロパティは持ち込まない |
| 採点API | 新設定を部品の`description`へ文字列化。接続設定は送信元部品に接続先ID付きで渡す。公開DTOは従来のscenario/nodes/edgesのまま |
| 採点サイズ上限 | 部品ごとの詳細合計2,000文字、説明・名称合計24,000文字、本文128KiBを送信前に確認。無言の切り捨てはしない。保存は続けられる |
| 評価との対応 | 新設定と接続設定の変更でも古い評価になる。戻すと一致状態を回復。幾何座標は採点から除外 |

自由メモ・会話全文は採点へ自動転送しない。採点に結びつけたい条件は、該当部品の「この部品で満たす条件と根拠」に明示的に記録する。将来、会話の合意を正式条件にするなら、サーバー側で確認された要件IDを導入する別の契約が必要。現在の「合意した」という文字列を権限として扱わない。

## ローカルでの振り返り

「設計を確かめる」はAI通信なし。記録からの事実、未確認、考える問いを分け、該当箇所へ戻れる。

障害の検討は、選択した論理部品全体の停止と有向グラフの到達性だけを計算する。VPC/AZ/Subnetは明示した参照をたどって停止範囲を広げる。旧囲み、SGの適用、台数の自動展開、条件分岐、キューの待機、応答時間、データ耐久性、料金、現実のフェイルオーバーは計算しない。代替経路が残っても成功を保証しない。

比較の基準は現在の作業中だけ保持し、閉じても維持する。再読み込みでは消える。差分結果と障害の検討結果は任意で既存のメモへ追記し、JSON保存できる。比較件数の増減を改善の証拠とはしない。
