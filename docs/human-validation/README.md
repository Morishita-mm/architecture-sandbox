# 人間による最終検証の引き継ぎ

自動化できる実装・本番・実Gemini受入は完了している。残る3項目は、人間の専門家2名とIT初学者5〜8名による観察が必要であり、AIや開発者の自己評価で代替しない。

## 専門家比較

1. 2名を選び、[手順](../evaluation-expert-review.md)を共有する。
2. 第1段階では[匿名入力](../evaluation-runs/2026-09-16/expert-inputs.json)と[入力判定票](../evaluation-runs/2026-09-16/expert-input-worksheet.json)だけを各人へ渡す。
3. 提出後にコピーを固定し、[匿名応答](../evaluation-runs/2026-09-16/expert-responses.json)と[応答判定票](../evaluation-runs/2026-09-16/expert-response-worksheet.json)を渡す。
4. 管理者だけが[対応表](../evaluation-runs/2026-09-16/expert-key.json)を開き、不一致と指標を集計する。

完了条件は2名の独立判定、相談前の不一致記録、合意または保留、専門家一致率・重大欠陥見逃し率・別解への誤判定の分子／分母が残ること。

## 初学者テスト

1. [実施台本](../usability-study.md)の対象条件に合う1名でパイロットを行う。
2. 答えを教える表現があれば台本だけを修正し、受入基準は結果を見て変更しない。
3. IT初学者5〜8名を実施し、[セッションシート](usability-session-sheet.md)を参加者ごとに複製する。観察前に本人の明示同意を記録し、同意がなければ開始も集計もしない。
4. 個票は公開リポジトリへ置かず、集計結果だけをIssue #5へ記録する。
5. 重大な誤解があればUIを修正し、未参加者で再確認する。

完了条件は、独力完走と説明が参加者の80%以上、別題材へ2観点を適用できる人が80%以上、安全性の誤認0件。割合は端数を切り上げる。未達の場合は完了扱いにせず、観測した画面と原因をIssueへ戻す。
