現在の画面・進捗仕様は、後続の[コンポーネント別ステージ](component-stages.md)（[Issue #8](https://github.com/Morishita-mm/architecture-sandbox/issues/8)）へ更新済み。以下は8章へ拡張した時点の実装・検証記録で、任意の章選択はステージの順次開放に変更した。見積もりは負荷分散の準備、設計判断は卒業課題として引き継いでいる。

## 方針

2026-09-15のユーザー依頼に基づくローカル開発。『システム設計の面接試験』（アレックス・シュウ、ソシム）の出版社公開情報を確認し、見積もり・スケール・要件に応じた設計という論点を参考にする。書籍本文の全体は参照しておらず、書籍の解説・図・問題の再現や章ごとの翻案は行わない。日常のお知らせサービスを題材にした独自教材として構成する。

参考: [出版社の書誌・公開目次](https://www.socym.co.jp/book/1406)。教材は書籍の公式教材ではなく、全内容を網羅するものでもない。

## 今回の章構成

| 章 | 学ぶ判断 | 比べる操作 |
| --- | --- | --- |
| 1 要求を届ける | 画面と処理の役割 | 接続あり／なしで送信 |
| 2 記録を残す | 一時記憶と保存先 | 保存して再起動、DBあり／なしで読み出す |
| 3 必要な量を見積もる | 平均だけで足りるか | 利用者・利用頻度・集中度を変えて必要量を計算 |
| 4 負荷を分けて止まりにくくする | 台数・振り分け・残る限界 | 1台／2台、1台停止、DBの処理上限を比較 |
| 5 読み出しを減らす | キャッシュの効率と鮮度 | 同じ内容を読む、元データ更新、キャッシュ無効化 |
| 6 重い仕事をあとで処理する | 受付と完了、再試行 | 同期／キュー、Worker停止、重複配信と重複防止 |
| 7 入口で受け付ける量を調整する | システム保護と利用者の待ち | 制限なし／あり、時間を進めて再試行 |
| 8 条件から設計を選ぶ | 必要な部品と代償を説明する | 別の条件で構成を比較し、設計メモと図を自由設計へ渡す |

1章ごとに「目的 → 予想する観点 → 操作 → 結果 → 仕組みと限界 → 役割の問い」の順に進める。追加部品を置くこと自体は達成としない。数値は教材で明示した仮定に基づく計算で、実サービスの性能予測や保証ではない。AI APIは追加しない。

## 教材データと調整箇所

- `frontend/src/constants/courseCurriculum.ts`: 章の目標・予想・操作手順・チェックポイント・用語・振り返り・仮定。文量や難易度の調整はここから行う。
- `frontend/src/utils/courseLabs.ts`: ブラウザ内の計算と状態遷移。観察済みの条件は操作した時点で記録し、設定を切り替えただけでは完了にしない。
- `frontend/src/components/CourseLab.tsx`: 第3〜8章の操作画面。目的・予想・手順は目標欄、仕組み・用語・負担・限界は実験結果の下で読める。
- `frontend/src/utils/courseProject.ts`: 第8章の選択から新しい自由設計プロジェクトを作る。既存の設計を上書きせず、選んだ構成・条件・理由・残る課題・教材の仮定を引き継ぐ。

学習記録は専用の`architecture-sandbox:learning-course:v2`キーへ保存。旧`v1`だけがある場合は2章の入力・観察・回答を読み込み、新章を初期状態で追加する。旧キーは削除しない。新形式の破損時に古い記録へ黙って戻すこともせず、警告と保存再試行を表示する。既存のプロジェクト用IndexedDBやJSON形式は拡張していない。

第8章の完了には比較操作、条件を満たした現在の構成、理由・残る課題の記述、振り返りが必要。記述の意味は採点しない。設定を変えたら再確認が必要。同じ条件を満たす構成は複数認め、部品の種類の多さを得点にしない。引き継ぎ後は構成図タブを開き、通常の部品編集・自動保存・JSON保存を利用できる。学習の途中でも、別の自由課題へ進める。

## 内容を確認した資料

構成の参考は書籍の公開情報。技術的な説明は次の一次資料で確認し、教材では表示した条件までに単純化した。

- [ソシム：システム設計の面接試験](https://www.socym.co.jp/book/1406) — 書誌・公開目次の見積もり、スケール、利用制限などの題材。
- [AWS：Application Load Balancerのターゲットグループ](https://docs.aws.amazon.com/elasticloadbalancing/latest/application/load-balancer-target-groups.html) — 正常な処理先へのルーティング。教材は停止検知済み・検知遅延なしを仮定する。
- [Redis：Cache-aside](https://redis.io/docs/latest/develop/use-cases/cache-aside/) — ヒット／ミス、元データからの取得、TTLや無効化。教材は手動無効化まで。
- [AWS：SQSの少なくとも1回の配信](https://docs.aws.amazon.com/en_gb/AWSSimpleQueueService/latest/SQSDeveloperGuide/standard-queues-at-least-once-delivery.html) — 再配信と冪等な処理。教材の処理済みIDと通知は単一の操作で更新する簡略モデル。
- [AWS：API Gatewayのスロットリング](https://docs.aws.amazon.com/apigateway/latest/developerguide/http-api-throttling.html) — トークンバケットと429。教材は手動の仮想時間と1つの箱で再現する。

教材の1台あたりの能力、利用量、キャッシュヒット率は実測値でも製品性能でもない。第3章は平均とピークの単位を学ぶ仮定、第4章以降は処理能力と経路を比べる別の仮定で、それぞれ画面で明示する。
